## 1. Verdict

The project is in good shape. The docs are the source of truth and the code follows them; secrets handling is deliberate (stdin login, 0600 files, scrubbed logs); removal is path-safe; every command is schema-checked; the JS libs are pure and heavily tested. The push pipeline was traced end to end (record → `shouldPush` → `enqueue` → flush re-read → `flushPlan` → `sendNext` → backend stale check) and no path was found that pushes a position the laptop did not produce.

The findings are edge-of-flow state bugs and hardening, not design flaws. The main maintenance risk is `Service.qml` (1125 lines) and the untested QML orchestration.

## 2. Findings

Severity: **H** fix before the next gate, **M** fix soon, **L** when touching the file. Each item says who owns it.

### 2.1 Position write-back (the phone follows a push silently)

| # | Sev | Owner | Finding |
|---|---|---|---|
| F1 | H | backend + desktop | **Clock-skew lockout.** The account stamps the laptop's own push with the server clock (ARCHITECTURE §4.6 says so). If the laptop clock is behind the server by more than the push interval, every later push returns `stale`, and `qml/PositionSync.qml:104` drops it from the queue with no UI signal. The phone never updates again. Fix: in `positions.push_position`, treat a remote entry whose `ms` equals the ms this laptop last pushed as our own echo (the rule `qml/lib/Catchup.js` already uses for resume), or allow a small tolerance. Surface a repeated `stale` in the Mini view. |
| F2 | H | backend (maintainer check) | **UTC assumption still inferred.** SPIKE-RESULTS S3 row "`last_updated` format" says treating it as UTC is inferred and B6 should confirm it against a write made at a known time. No STATE row records that confirmation. Do one real push, read it back, compare `last_updated` with the wall clock, and record the result in SPIKE-RESULTS. |
| F3 | M | backend | **Stale check is a no-op without `--at`.** `positions.py:364` defaults `listening_at` to now when `--at` is absent, so the check can never fire. QML always passes `at` today (`Sync.pushArgs`). The backend should refuse `position-push` without `--at` (`invalid_args`) rather than trust the default. |

### 2.2 Backend (`backend/omarchy_audible/`)

| # | Sev | Finding |
|---|---|---|
| F4 | M | **Scrubber allowlist gaps** (`log.py:13-25`). The regexes need a word boundary before the key name and `_` is a word character, so `device_private_key`, `adp_token`, `website_cookies`, `store_authentication_cookie` are not masked (verified by running `scrub`). Exposure is low because most call sites log `type(exc).__name__` only, but `download.py:411` logs `exc!r`. Fix: match on a suffix, `[\w.-]*(token|key|secret|cookie|password|verifier|iv)\b`, extend the tests in `tests/test_log.py` with an `auth.json`-shaped dict, and change `download.py:411` to the type name. |
| F5 | M | **Login persist order** (`auth.py:525-532`). After `register` succeeds, `get_activation_bytes()` (a network call) runs before `auth.to_file`. If it fails the device stays registered at Amazon with nothing saved, and the hint "start the login again" registers another device each time. Fix: persist `auth.json`, `config.toml`, `account.json` first; fetch activation bytes best-effort and lazily (on `b11` only an aax book needs them, at play time). |
| F6 | M | **Second SIGTERM aborts cleanup** (`commands.py:291-304`, `download.py:706-710`). `_sigterm_cancels._raise` raises `Cancelled` from the handler; a second SIGTERM (the UI killing the pid after `cancel`, or two cancels) lands inside the `finally` during `tracker.terminate_all()` and `.partial/` survives. Fix: in `_raise`, set `SIG_IGN` before raising so the second signal is ignored; keep the existing test for the first cancel and add one for the double signal. |
| F7 | M | **`b11` re-download destroys the working copy first** (`download.py` on `b11`, `_clear_local(target_dir)` before the fetch). A `get` on an already-local book deletes `book.*`, `key.json`, `chapters.txt`, `meta.json`, then starts the download; if it fails the user has lost a playable book. On `main` the old `book.m4b` survived until the atomic rename. Fix: write `key.json` and `chapters.txt` into `.partial/`, verify there, then clear the old files and move everything in as the last step. |
| F8 | L | **aax fallback on any aaxc error** (`download.py:588-592`). An offline `get` fails twice and reports the aax error. Fall back only on `no_voucher`. |
| F9 | L | **audible-cli stderr is discarded** (`download.py:493`, `quiet=True`), so a real download failure logs nothing. Write it to `.partial/audible.stderr` and log the scrubbed last line on failure. |
| F10 | L | Free-space pre-flight (`download.py:682`) runs before the old `.partial/` and, on `b11`, the old book are removed, so a retry can be refused for space the old copy itself holds. |
| F11 | L | `position-get` (read-modify-write) and `sync` (snapshot) both write `remote.json`; one is a job and one is not, so they can overlap and last writer wins. Atomic writes avoid corruption. Note it, or have `sync` merge instead of replace. |
| F12 | L | Cover fetch in `sync` is serial `urllib` with a 20 s timeout each and no progress events; a first sync on a large library is slow and silent. Emit `progress stage=covers n/of`. |
| F13 | L | `paths._runtime_dir` fallback `/tmp/omarchy-audible-<uid>` is created with the default mode; create it `0700`. |
| F14 | L | `protocol.write_event` uses `ensure_ascii=False`; add `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` in `cli.main` so a C-locale shell cannot raise on a non-ASCII message. |
| F15 | L | `status.authenticated` is `auth_file.is_file()`; FR-A4 (expired or revoked → Reconnect banner) currently relies on `sync` failing with `auth_failed`. Fine for v1; record the gap under R2. |

### 2.3 QML and JS (`Service.qml`, `qml/`)
